Продолжи разработку приложения Aitu Dating на основе текущей версии прототипа
Внеси все изменения из этого задания в существующее приложение. Сохрани текущую архитектуру, существующие рабочие экраны, русский Threads-style и действующие правила безопасности, если они не противоречат требованиям ниже.
Не создавай новые основные разделы без необходимости. Используй существующие экраны, профили, ленты, карточки встреч, чаты и модальные окна там, где это возможно.
Все пользовательские тексты должны быть на русском языке.
==================================================
1. ОСНОВНАЯ КОНЦЕПЦИЯ
==================================================
Aitu Dating — закрытое сообщество знакомств, где пользователи знакомятся через:
- публикации;
- анкеты;
- профили;
- комментарии;
- личные сообщения;
- встречи один на один.
Основной интерфейс должен оставаться похожим на русский Threads-style:
- спокойная текстовая лента;
- компактные карточки;
- минималистичная навигация;
- публикации и комментарии;
- профили пользователей;
- понятные действия;
- отсутствие свайпов как основного механизма знакомств.
Встречи всегда только один на один.
При нажатии кнопки «＋» пользователь может создавать только:
- пост;
- встречу.
Отдельный тип «Вопрос» удалить.
Главное правило переписки:
Всеверифицированные пользователи могут писать друг другу без ограничений, если между ними нет блокировки.
==================================================
2. ПЕРЕИМЕНОВАНИЯ
==================================================
Замени названия во всём пользовательском интерфейсе:
- «Для тебя» → «Поиск».
- «Подписки» → «Мои подписки».
- «План» → «Встреча».
- «Планы встреч» → «Встречи».
- «Гость» → «Неверифицированный пользователь».
- «Участник» → «Верифицированный пользователь».
- «Участник с истёкшим membership» → «Верифицированный пользователь с истёкшим сроком подписки».
Переименования должны быть применены:
- на экранах;
- в нижней навигации;
- в карточках;
- в фильтрах;
- в профилях;
- в уведомлениях;
- в чатах;
- в кнопках;
- в подсказках;
- в демо-данных;
- в сообщениях об ошибках;
- в пустых состояниях;
- в модальных окнах.
В коротких местах, где полное название не помещается, допускаются варианты:
- «Неверифицированный»;
- «Верифицированный»;
- «Верификация истекла».
В подробных экранах статуса и профиля используй полные названия.
В пользовательском интерфейсе больше не используй слово «план». Везде используй слово «встреча».
==================================================
3. ЛЕНТЫ
==================================================
На главном экране должны быть три ленты:
1. «Поиск».
2. «Популярное».
3. «Мои подписки».
Лента «Поиск» заменяет старую ленту «Для тебя».
Лента «Мои подписки» заменяет старую ленту «Подписки».
Лента «Поиск»:
- показывает доступные публикации и встречи сообщества;
- использует данные анкеты пользователя;
- использует выбранные фильтры;
- может показывать релевантные публикации, встречи и людей;
- не показывает заблокированных пользователей;
- не показывает удалённые публикации;
- не показывает недоступные или ограниченные объекты.
Лента «Мои подписки»:
- показывает публикации и встречи только пользователей, на которых подписан текущий пользователь;
- использует абсолютно такой же фильтр, как лента «Поиск»;
- имеет те же поля;
- имеет те же переключатели;
- имеет те же кнопки «Применить», «Сбросить» и «Отмена».
Разница между лентами должна быть только в источнике данных:
- «Поиск» — всё доступное сообщество;
- «Мои подписки» — только авторы, на которых подписан пользователь.
В обеих лентах должны быть одинаковые переключатели:
- «Все»;
- «Посты»;
- «Встречи».
Посты и встречи могут отображаться в одной ленте, но должны визуально различаться по типу карточки.
Прошедшие, отменённые и закрытые встречи не показывай среди активных результатов поиска. Они могут оставаться:
- в профиле автора;
- в истории;
- в чатах;
- в уведомлениях;
- в списке собственных встреч.
==================================================
4. ЕДИНЫЙ ФИЛЬТР ДЛЯ ЛЕНТ
==================================================
Создай один общий фильтр, который используется в лентах «Поиск» и «Мои подписки».
Фильтр должен позволять выбирать:
- тип содержимого: «Все», «Посты», «Встречи»;
- город или населённый пункт;
- интересы;
- темы;
- намерения;
- формат встречи;
- цель встречи;
- дату;
- ближайшие даты;
- другие уже утверждённые параметры встреч.
Не создавай две независимые версии фильтра.
Фильтр должен открываться через кнопку:
«Фильтры»
На экране фильтра должны быть кнопки:
- «Применить»;
- «Сбросить»;
- «Отмена».
После применения выбранные параметры показывай в виде компактных чипов или меток.
Фильтры должны сохраняться:
- при переходе между лентами;
- при открытии публикации;
- при открытии профиля;
- после возврата назад;
- после повторного открытия приложения.
Если пользователь выбирает несколько значений, фильтрация должна учитывать совпадение хотя бы по одному выбранному варианту.
==================================================
5. КНОПКА «＋» И ТИПЫ СОЗДАНИЯ
==================================================
После нажатия кнопки «＋» в нижнем меню пользователь должен видеть только два варианта:
1. «Создать пост».
2. «Создать встречу».
Отдельный тип «Вопрос» полностью удалить.
Новые вопросы не создавай как отдельный тип публикации.
Если в старых демо-данных уже есть публикации с вопросами, отображай их как обычные посты с вопросительным текстом.
Не добавляй отдельный пункт «Цитата» в меню создания.
Цитирование может оставаться действием под чужой публикацией. При нажатии «Цитировать» открывай создание обычного поста с прикреплённой карточкой исходной публикации.
==================================================
6. СОЗДАНИЕ ПОСТА
==================================================
Сохрани и обнови существующий экран создания поста.
Пользователь может:
- написать до 1000 символов;
- добавить до 1 фотографии;
- удалить фотографии до публикации;
- просмотреть предпросмотр;
- отменить создание;
- опубликовать пост;
- сохранить черновик при ошибке или выходе.
После публикации пост должен появиться:
- в ленте;
- в профиле автора;
- в результатах поиска;
- в ленте «Мои подписки», если пользователь подписан на автора.
При ошибке публикации:
- текст не должен исчезать;
- выбранные фотографии не должны исчезать;
- выбранные темы не должны исчезать;
- пользователь должен увидеть причину ошибки;
- должна быть кнопка «Повторить».
Если фотография создана с помощью искусственного интеллекта, под ней обязательно показывай точную подпись:
«Сгенерировано с ИИ»
Используй именно это написание во всех постах и встречах.
Подпись должна добавляться автоматически по источнику фотографии, а не на основании текста пользователя.
Для каждой фотографии должно быть понятно, является ли она:
- обычной загруженной фотографией;
- фотографией, созданной искусственным интеллектом.
Подпись «Сгенерировано с ИИ» показывай только под изображениями, созданными искусственным интеллектом.
Для обычных фотографий эту подпись не показывай.
==================================================
7. СОЗДАНИЕ ВСТРЕЧИ
==================================================
Создай или обнови экран создания встречи.
Встречи всегда только один на один. Групповые встречи не добавляй.
Форма встречи должна содержать:
- город или населённый пункт;
- дату;
- время;
- формат встречи;
- продолжительность;
- цель встречи;
- кто платит;
- бюджет на человека;
- описание;
- примерное место;
- точное место;
- одну фотографию;
- темы встречи.
К одной встрече можно добавить только одну фотографию.
Точное место должно быть скрыто от остальных пользователей до принятия запроса.
Точное место видят только:
- автор встречи;
- пользователь, чей запрос был принят.
При указании точного места автор должен подтвердить, что это публичное место.
Встреча должна иметь статусы:
- «Открыта»;
- «Запрос отправлен»;
- «Набор закрыт»;
- «Отменена»;
- «Прошла»;
- «Удалена»;
- «Недоступна».
После публикации встреча появляется:
- в ленте «Поиск»;
- в ленте «Мои подписки», если пользователь подписан на автора;
- в разделе «Встречи» профиля автора;
- в результатах поиска встреч.
Если фотография встречи создана искусственным интеллектом, под ней показывай:
«Сгенерировано с ИИ»
==================================================
8. ПОЛНЫЙ СПРАВОЧНИК НАСЕЛЁННЫХ ПУНКТОВ КАЗАХСТАНА
==================================================
В анкете должен использоваться полный структурированный справочник населённых пунктов Казахстана.
Нельзя ограничиваться только:
- Алматы;
- Астаной;
- Шымкентом;
- Карагандой;
- несколькими крупными городами.
Используй полный утверждённый справочник, включающий:
- города;
- районные центры;
- посёлки;
- сёла;
- другие населённые пункты Казахстана, доступные в справочнике.
Выбор населённого пункта должен быть удобным для мобильного устройства:
- поиск по названию;
- сортировка по совпадению;
- отображение области или региона;
- структурирование по области;
- структурирование по району;
- возможность выбрать один текущий населённый пункт;
- вариант для пользователя, который не хочет указывать город.
Не показывай все населённые пункты одним длинным неструктурированным списком.
В анкете, профиле, фильтрах, встречах и поиске используй один и тот же справочник и одинаковые названия.
==================================================
9. АНКЕТА ПОЛЬЗОВАТЕЛЯ
==================================================
В анкете должны быть следующие вопросы:
1. В каком городе или населённом пункте ты сейчас живёшь?
2. Что ты сейчас ищешь?
3. Как тебе комфортнее начинать общение?
4. Какой темп знакомства тебе подходит?
5. Как лучше провести первую встречу?
6. Что важно для безопасного общения?
7. Какой формат встречи тебе ближе?
Добавь множественный выбор там, где это логично.
Правила выбора:
- населённый пункт — до 2 вариантов;
- намерения — до 3 вариантов;
- способы начала общения — до 2 вариантов;
- темп знакомства — один вариант;
- варианты первой встречи — до 2 вариантов;
- правила безопасного общения — несколько вариантов;
- формат встречи — до 3 вариантов.
Рядом с ограниченными вопросами показывай подсказку:
«Выберите до 3 вариантов» или соответствующее ограничение.
Ответы анкеты должны использоваться:
- в профиле;
- в ленте «Поиск»;
- в ленте «Мои подписки»;
- в фильтрах;
- в подборе публикаций;
- в подборе встреч;
- в рекомендациях.
Если пользователь выбрал несколько вариантов, совпадением считается наличие хотя бы одного общего варианта.
==================================================
10. РЕДАКТИРОВАНИЕ АНКЕТЫ
==================================================
В собственной анкете добавь кнопку:
«Редактировать анкету»
Пользователь должен иметь возможность изменить:
- город или населённый пункт;
- намерения;
- интересы;
- стиль общения;
- ответы анкеты;
- информацию «О себе»;
- фотографии;
- предпочтительные форматы общения;
- предпочтительные форматы встреч.
Добавь кнопки:
- «Сохранить изменения»;
- «Отменить изменения».
Если пользователь выходит без сохранения, показывай предупреждение:
«У вас есть несохранённые изменения. Выйти без сохранения?»
Данные Aitu Passport, факт верификации и системные данные пользователя обычным редактированием не изменяются.
После сохранения новые ответы должны использоваться:
- в профиле;
- в поиске;
- в фильтрах;
- в рекомендациях;
- в подборе встреч;
- в ленте «Поиск»;
- в ленте «Мои подписки».
==================================================
11. ПРОФИЛИ
==================================================
Собственный профиль должен содержать:
- имя;
- возраст;
- город или населённый пункт;
- отметку верификации;
- фотографию;
- информацию «О себе»;
- намерения;
- интересы;
- стиль общения;
- ответы анкеты;
- статус подписки;
- посты;
- встречи;
- кнопку «Редактировать анкету»;
- кнопку или действие удаления собственных постов и встреч.
В собственном профиле добавь переключатель:
- «Все»;
- «Посты»;
- «Встречи».
В профиле другого пользователя также добавь этот переключатель.
В профиле другого пользователя должны быть видны его публикации и встречи с учётом правил доступа.
Пользователь должен иметь возможность выбирать:
- только посты;
- только встречи;
- все публикации.
В профиле другого пользователя добавь кнопку:
«Написать сообщение»
После нажатия открывай чат с этим пользователем.
==================================================
12. ОБЩЕЕ ПРАВИЛО ПЕРЕПИСКИ
==================================================
Измени прежнее правило контекстных чатов.
Новое правило:
«Все пользователи могут писать друг другу без ограничений».
Это означает:
- любой верифицированный пользователь может написать другому верифицированному пользователю;
- не требуется взаимная подписка;
- не требуется принятие запроса на встречу;
- не требуется предварительный комментарий;
- не требуется специальный контекст;
- количество сообщений не ограничивается;
- кнопка «Написать сообщение» в профиле открывает чат напрямую.
Правило распространяется на верифицированных пользователей.
Неверифицированные пользователи и верифицированные пользователи с истёкшим сроком подписки не могут отправлять сообщения.
У каждой пары пользователей должен быть один общий чат.
Не создавай отдельные дублирующиеся чаты для:
- профиля;
- встречи;
- запроса;
- приглашения;
- комментария.
Кнопка «Перейти в чат» на встрече должна открывать тот же общий чат с автором встречи.
Если чат уже существует, открывай существующий чат.
В чате должны быть:
- текстовые сообщения;
- возможность отправить одну фотографию в сообщении, если эта возможность уже предусмотрена;
- статус отправки;
- статус прочтения;
- кнопка повторной отправки при ошибке;
- кнопка «Поделиться»;
- кнопки «Пожаловаться» и «Заблокировать».
Свободная переписка не отменяет правила блокировки и жалоб.
==================================================
ТИПЫ СООБЩЕНИЙ В ЧАТЕ
==================================================
В чате пользователь должен иметь возможность отправлять три типа сообщений:
1. Текстовые сообщения.
2. Голосовые аудиосообщения.
3. Фотографии.
### Текстовые сообщения
Пользователь может отправлять текстовые сообщения без ограничения количества.
Текстовое сообщение должно поддерживать:
- ввод текста;
- отправку;
- отображение статуса отправки;
- отображение статуса прочтения;
- повторную отправку при ошибке;
- сохранение текста при отсутствии сети или ошибке отправки.
### Голосовые аудиосообщения
Пользователь может записывать и отправлять голосовые аудиосообщения прямо в чате.
В интерфейсе должны быть доступны:
- кнопка начала записи;
- отображение длительности записи;
- возможность отменить запись до отправки;
- возможность прослушать запись перед отправкой, если это поддерживается текущим интерфейсом;
- кнопка отправки;
- отображение аудиосообщения в чате;
- воспроизведение и пауза;
- отображение длительности аудиосообщения;
- состояние загрузки;
- состояние ошибки;
- кнопка «Повторить» для неотправленного аудиосообщения.
При записи пользователь должен явно видеть, что запись идёт.
Если пользователь отменил запись, аудиофайл не отправляется.
Если отправка не удалась, аудиосообщение не должно исчезать без объяснения. Показывай состояние:
«Не отправлено»
и кнопку:
«Повторить»
Ограничь максимальную длительность одного голосового сообщения понятным значением, подходящим для первой версии приложения. Показывай оставшееся или прошедшее время во время записи.
### Фотографии
Пользователь может прикреплять и отправлять фотографии в чате.
Добавь возможность:
- выбрать фотографию из галереи;
- прикрепить фотографию к сообщению;
- увидеть предпросмотр до отправки;
- удалить фотографию до отправки;
- отменить загрузку;
- отправить фотографию;
- повторить отправку при ошибке.
Ограничь размер одного отправляемого файла. Максимальный вес фотографии должен быть явно указан в интерфейсе, например:
«Максимальный размер фото — 10 МБ»
Если файл превышает ограничение, не отправляй его и показывай понятное сообщение:
«Фото слишком большое. Максимальный размер — 10 МБ»
Поддерживай распространённые форматы фотографий:
- JPG;
- PNG;
- WEBP.
Перед отправкой слишком большую фотографию можно сжать или уменьшить, если это не ухудшает пользовательский опыт. Если после обработки размер всё равно превышает лимит, покажи ошибку и предложи выбрать другое фото.
В чате фотография должна отображаться:
- с состоянием загрузки;
- после успешной отправки;
- с состоянием «Не отправлено» при ошибке;
- с кнопкой «Повторить» при ошибке.
Для фотографий в чате должны действовать существующие правила безопасности, доступа и блокировки.
### Общие правила для всех типов сообщений
Текст, голосовые сообщения и фотографии должны использовать один общий чат между двумя пользователями.
Не создавай отдельные чаты для разных типов сообщений.
Каждое сообщение должно иметь понятное состояние:
- «Отправляется»;
- «Отправлено»;
- «Прочитано»;
- «Не отправлено».
При отсутствии сети:
- не удаляй введённый текст;
- не удаляй подготовленную фотографию;
- не удаляй записанное аудиосообщение;
- показывай состояние ошибки;
- предлагай кнопку «Повторить».
Повторная отправка не должна создавать дубликат сообщения, если предыдущее сообщение уже было успешно принято.
Заблокированный пользователь не может отправлять новые текстовые сообщения, голосовые аудиосообщения и фотографии.
После блокировки уже отправленные сообщения не удаляй автоматически, если это не предусмотрено существующими правилами модерации. Новые сообщения должны быть недоступны.
Для фотографий и аудиосообщений сохраняй действующие ограничения безопасного доступа. Пользователь должен видеть только те материалы, к которым у него есть доступ.
==================================================
13. ПРАВИЛА БЛОКИРОВКИ
==================================================
Если один пользователь заблокировал другого:
- заблокированный пользователь не может отправлять сообщения;
- заблокированный пользователь не может получать новые сообщения;
- кнопка «Написать сообщение» недоступна;
- кнопка «Перейти в чат» недоступна;
- чат недоступен для переписки;
- заблокированный пользователь не видит встречи заблокировавшего его пользователя;
- заблокированный пользователь не может отправлять новые запросы;
- заблокированный пользователь не отображается в поиске получателей;
- заблокированный пользователь не может отправить приглашение.
Блокировка должна работать одинаково:
- в профиле;
- в чате;
- в списке запросов;
- из карточки встречи;
- из меню публикации, если это уже предусмотрено.
После блокировки состояние интерфейса должно обновляться сразу.
Правила жалоб и модерации сохраняются.
==================================================
14. ПРАВИЛА ДОСТУПА И БЕЗОПАСНЫЙ ПРОСМОТР
==================================================
Сохрани безопасный просмотр для неверифицированных пользователей.
Неверифицированный пользователь может:
- читать ленту;
- читать посты;
- читать комментарии в ограниченном виде;
- видеть пол, возраст и город автора;
- видеть нейтральный силуэт вместо аватара;
- видеть фотографии с блюром;
- видеть встречи без точного места;
- видеть безопасную общую информацию;
- писать другим пользователям через чат, если нет блокировки;
- открывать внешние ссылки на встречи в безопасном виде;
- делиться доступной встречей, если это разрешено текущим уровнем доступа и нет блокировки.
Неверифицированный пользователь не должен видеть:
- полное имя автора;
- настоящий аватар;
- интересы;
- намерения;
- ответы анкеты;
- точное место встречи;
- закрытые персональные данные;
- полную закрытую информацию профиля;
- оригинальную фотографию, если она должна быть доступна только в ограниченном виде.
Верифицированный пользователь может:
- видеть полные профили в рамках правил приложения;
- видеть имена и аватары;
- создавать посты;
- создавать встречи;
- комментировать;
- подписываться;
- отправлять запросы на встречи;
- пользоваться чатами;
- писать любым пользователям, кроме заблокировавших его;
- редактировать свою анкету;
- удалять свои посты и встречи;
- делиться встречами;
- получать персональные приглашения;
- отправлять персональные приглашения.
Верифицированный пользователь с истёкшим сроком подписки:
- сохраняет собственный профиль и анкету;
- может редактировать собственную анкету;
- не может писать в чаты;
- может читать старые чаты;
- видит других пользователей с учётом правил безопасного просмотра для неверифицированных пользователей – то есть также как неверифицированные пользователи;
- не может создавать новые посты;
- не может создавать новые встречи;
- не может отправлять запросы на встречи;
- вместо недоступных действий видит кнопку «Продлить подписку».
Свободная переписка не отменяет ограничений на создание постов, встреч и запросов для неверифицированных пользователей и пользователей с истёкшим сроком подписки.
Скрытые данные нельзя просто маскировать на экране. Если пользователь не имеет доступа, ему нельзя передавать оригинальную фотографию или запрещённую информацию в полном виде.
==================================================
15. УДАЛЕНИЕ СОБСТВЕННЫХ ПОСТОВ И ВСТРЕЧ
==================================================
Пользователь в собственном профиле должен иметь возможность удалить:
- свои посты;
- свои встречи.
Перед удалением показывай подтверждение.
Для поста используй текст:
«Удалить этот пост? Он исчезнет из ленты и профиля.»
Для встречи используй текст:
«Удалить эту встречу? Она исчезнет из поиска, а все ожидающие запросы будут отменены.»
После удаления:
- пост исчезает из активной ленты;
- пост исчезает из поиска;
- встреча больше не принимает запросы;
- ожидающие запросы отменяются;
- связанные уведомления не ломают приложение;
- существующий чат не удаляется автоматически;
- ранее отправленные карточки встречи сохраняются в чатах с актуальным статусом.
Если пользователь открыл старую ссылку на удалённую публикацию, показывай:
«Публикация недоступна»
==================================================
16. ЗАПРОСЫ НА ВСТРЕЧИ
==================================================
На экране открытой чужой встречи для верифицированного пользователя должны отображаться две отдельные кнопки:
- «Отправить запрос»;
- «Перейти в чат».
Кнопка «Отправить запрос» позволяет отправить автору встречи запрос и короткое сообщение.
После отправки показывай:
«Запрос отправлен»
Также должны быть доступны:
- «Отозвать запрос»;
- просмотр статуса запроса;
- просмотр отправленного сообщения.
Один пользователь не может отправить несколько одинаковых активных запросов на одну встречу.
Кнопка «Перейти в чат» должна открывать общий чат с автором встречи независимо от того, принят запрос или нет, потому что все пользователи могут писать друг другу без ограничений.
После принятия запроса:
- встреча получает статус «Встреча договорена»;
- точное место становится видно автору и принятому участнику;
- у обоих остаётся кнопка «Перейти в чат»;
- остальные ожидающие запросы автоматически отклоняются;
- новые запросы больше не принимаются.
Автор встречи может:
- принять запрос;
- отклонить запрос;
- закрыть набор;
- отменить встречу;
- перейти в чат;
- заблокировать пользователя.
Неверифицированный пользователь не может отправлять запросы на встречи. При попытке выполнить это действие показывай предложение пройти верификацию.
При этом общий чат для него должен оставаться доступным согласно правилу свободной переписки, если нет блокировки.
==================================================
17. УВЕДОМЛЕНИЯ О ВСТРЕЧАХ
==================================================
Автор встречи должен получать уведомление:
«Пользователь отправил запрос на вашу встречу»
Нажатие на уведомление должно открывать конкретную встречу и список запросов.
Добавь или сохрани следующие уведомления:
- «Ваш запрос на встречу отправлен»;
- «Ваш запрос на встречу принят»;
- «Ваш запрос на встречу отклонён»;
- «Встреча отменена»;
- «Автор встречи закрыл набор»;
- «Пользователь заблокирован»;
- «На ваш пост ответили»;
- «На вас подписались»;
- «Ваш пост понравился другому пользователю»;
- «Срок подписки скоро истечёт».
Сообщения из чатов не смешивай с уведомлениями. Они должны оставаться:
- в разделе «Сообщения»;
- внутри общего чата.
==================================================
18. КАРТОЧКА ВСТРЕЧИ В ЧАТЕ ПОСЛЕ ЗАПРОСА
==================================================
Если пользователь отправил запрос на встречу, в общем чате между пользователем и автором встречи автоматически должно появиться системное сообщение с карточкой этой встречи.
Карточка должна быть связана именно с конкретной встречей.
Карточка должна содержать доступную получателю информацию:
- название или краткое описание встречи;
- город или населённый пункт;
- дату и время;
- формат встречи;
- продолжительность;
- цель встречи;
- бюджет и информацию о том, кто платит, если эти данные доступны;
- фотографию в безопасном виде;
- текущий статус запроса;
- кнопку или ссылку «Открыть встречу».
После отправки запроса в чате можно показывать текст:
«Вы отправили запрос на встречу»
Нажатие на «Открыть встречу» должно открывать конкретную карточку этой встречи, а не общий список встреч.
Если автор принимает запрос, карточка в чате должна обновиться и показать:
«Встреча договорена»
Если запрос отклонён, отозван, встреча отменена или удалена, статус карточки должен обновиться:
- «Запрос отклонён»;
- «Запрос отозван»;
- «Встреча отменена»;
- «Встреча удалена»;
- «Встреча недоступна»;
- «Встреча уже прошла».
История карточки должна сохраняться в чате даже после отмены или удаления встречи.
Точное место отображай только автору встречи и участнику, чей запрос был принят.
Не показывай точное место через ссылку или карточку пользователю без соответствующего права доступа.
==================================================
19. ПОДЕЛИТЬСЯ ВСТРЕЧЕЙ
==================================================
Под карточкой встречи добавь отдельную кнопку:
«Поделиться»
Кнопка должна быть доступна автору встречи и другим пользователям, которым разрешено просматривать эту встречу.
После нажатия открывай меню выбора способа отправки:
- «Поделиться в Aitu Dating»;
- «Поделиться через другое приложение»;
- «Скопировать ссылку».
Не создавай новую встречу. Во всех случаях используй ссылку на существующую конкретную встречу.
==================================================
20. ПОДЕЛИТЬСЯ В AITU DATING
==================================================
При выборе «Поделиться в Aitu Dating» открывай экран или нижний лист:
«Поделиться встречей»
На этом экране пользователь выбирает другого пользователя, которому хочет отправить ссылку на встречу.
Добавь поиск пользователей для выбора получателя.
Поиск должен работать:
- по имени;
- по имени пользователя, если оно используется;
- по городу;
- по другим открытым данным, доступным текущей роли пользователя.
В результатах выбора показывай только пользователей, которым разрешено отправить сообщение.
Не показывай:
- заблокированных пользователей;
- пользователей, заблокировавших текущего пользователя;
- удалённые профили;
- недоступные профили;
- самого текущего пользователя.
В результатах поиска показывай только минимально необходимую информацию:
- доступное имя или безопасное обозначение;
- аватар или безопасный силуэт;
- город, если он доступен текущей роли.
Не раскрывай через поиск скрытые данные профиля.
После выбора пользователя отправляй ссылку на встречу в общий чат между отправителем и выбранным получателем.
Если общий чат уже существует, используй его.
Если общего чата ещё нет, создай один общий чат между этими пользователями.
Не создавай отдельный чат специально для встречи, запроса или приглашения.
Отправленное сообщение должно содержать:
- карточку встречи;
- короткий текст приглашения;
- кнопку «Открыть встречу».
Отправитель может добавить личное сообщение.
Карточка должна содержать только информацию, доступную получателю согласно его роли.
==================================================
21. ПОДЕЛИТЬСЯ ЧЕРЕЗ ДРУГИЕ ПРИЛОЖЕНИЯ
==================================================
При выборе «Поделиться через другое приложение» открывай стандартное системное меню общего доступа, используемое современными мобильными устройствами.
В системном меню должны быть доступны установленные на устройстве приложения и системные действия, например:
- WhatsApp;
- Telegram;
- другие мессенджеры;
- SMS;
- электронная почта;
- заметки;
- социальные приложения;
- копирование ссылки;
- другие приложения, поддерживающие системное меню общего доступа.
Не ограничивай список только WhatsApp и Telegram. Показывай все доступные приложения, которые предлагает операционная система устройства.
Внешнее сообщение должно содержать:
- название или краткое описание встречи;
- город;
- дату и время;
- формат встречи;
- безопасную ссылку на конкретную встречу;
- короткий текст-приглашение.
Пример:
«Хочу пригласить тебя на встречу в Aitu Dating. Открыть встречу: [ссылка]»
Если у встречи нет названия, используй:
«Приглашение на встречу в Aitu Dating»
Ссылка должна вести именно на карточку конкретной встречи, а не на общий список встреч и не на главную страницу.
Если приложение Aitu Dating установлено, ссылка должна открывать конкретную встречу внутри приложения.
Если приложение не установлено, ссылка должна открывать безопасную веб-страницу или страницу-прослойку с информацией о встрече и предложением открыть или установить Aitu Dating.
Внешняя ссылка не должна раскрывать:
- точное место встречи;
- полное имя автора для неверифицированного получателя;
- закрытую информацию профиля;
- ответы анкеты;
- приватные данные;
- оригинальную фотографию, если получателю запрещён доступ к ней.
До принятия запроса точное место никогда не включай во внешнюю ссылку или внешнее сообщение.
Если пользователь открывает ссылку без авторизации, он должен увидеть безопасную версию встречи.
Если пользователь входит в Aitu Dating и получает право полного просмотра, карточка встречи должна открыться с соответствующим уровнем доступа.
==================================================
22. СКОПИРОВАТЬ ССЫЛКУ
==================================================
При выборе «Скопировать ссылку» скопируй ссылку на конкретную встречу в буфер обмена.
После копирования показывай:
«Ссылка на встречу скопирована»
Ссылка должна вести на конкретную карточку встречи.
Не включай в ссылку:
- точное место;
- закрытые данные автора;
- ответы анкеты;
- приватные данные;
- оригинальную фотографию для пользователя без соответствующего доступа.
==================================================
23. КНОПКА «ПОДЕЛИТЬСЯ» В ЧАТЕ
==================================================
В существующем чате добавь кнопку или действие:
«Поделиться»
При нажатии этой кнопки не нужно повторно искать пользователя. Получателем автоматически становится текущий собеседник.
После нажатия открывай экран:
«Выберите встречу для отправки»
Показывай встречи, которыми текущий пользователь имеет право поделиться.
По умолчанию показывай:
- собственные открытые будущие встречи;
- собственные встречи, доступные для приглашения;
- встречи, которые не отменены;
- встречи, которые не удалены;
- встречи, которые ещё не прошли.
Не показывай как новые приглашения:
- удалённые встречи;
- отменённые встречи;
- прошедшие встречи;
- встречи, для которых закрыта возможность приглашений;
- встречи, недоступные получателю;
- встречи, которыми пользователь не имеет права делиться.
После выбора встречи отправляй в текущий чат карточку выбранной встречи с кнопкой:
«Открыть встречу»
Сообщение должно быть понятно как персональное приглашение:
«Хочу пригласить тебя на эту встречу»
или
«Пользователь поделился встречей»
Если пользователь хочет отправить ссылку через стороннее приложение из чата, он может открыть карточку встречи и нажать расположенную под ней кнопку «Поделиться».
После этого должны быть доступны те же варианты:
- «Поделиться в Aitu Dating»;
- «Поделиться через другое приложение»;
- «Скопировать ссылку».

24. ПРАВИЛА ССЫЛОК И СТАТУСОВ ВСТРЕЧ
==================================================
Во всех вариантах используй одну и ту же ссылку на конкретную встречу:
- при отправке в Aitu Dating;
- при отправке карточки в чате;
- при отправке через WhatsApp, Telegram и другие приложения;
- при копировании ссылки.
Внутри приложения ссылка открывает карточку встречи.
Во внешнем приложении ссылка открывает безопасную веб-страницу или приложение Aitu Dating.
Если встреча доступна, пользователь видит соответствующие действия:
- «Отправить запрос»;
- «Перейти в чат»;
- «Открыть профиль автора», если это разрешено.
Если встреча отменена, удалена, завершена или недоступна, карточка должна показывать актуальное состояние:
- «Встреча отменена»;
- «Встреча удалена»;
- «Встреча недоступна»;
- «Встреча уже прошла».
История сообщения и карточки сохраняется в чате.
Если встреча уже договорена с другим пользователем, показывай:
«Встреча уже договорена»
Не позволяй отправлять новый запрос, если это запрещено текущим статусом встречи.
Если отправитель заблокирован получателем или получатель заблокирован отправителем:
- нельзя отправить приглашение через Aitu Dating;
- нельзя отправить ссылку через внешний канал;
- нельзя открыть общий чат;
- кнопка «Поделиться» недоступна или показывает объяснение;
- запрещённые данные не раскрываются.
Если пользователь пытается поделиться встречей с самим собой, показывай:
«Нельзя отправить встречу самому себе»

25. ЕДИНЫЕ ПРАВИЛА ДЛЯ ПОДЕЛИТЬСЯ
==================================================
Должны работать два основных сценария.
Сценарий 1:
Пользователь нажимает «Поделиться» под карточкой встречи.
Затем выбирает:
- пользователя в Aitu Dating;
- стороннее приложение;
- копирование ссылки.
Сценарий 2:
Пользователь открывает существующий чат и нажимает «Поделиться».
Затем выбирает встречу и отправляет её текущему собеседнику.
В обоих сценариях:
- используется ссылка на конкретную встречу;
- внутреннее сообщение отправляется в общий чат;
- внешнее сообщение отправляется через системное меню;
- доступны WhatsApp, Telegram и другие установленные приложения;
- действуют одинаковые правила блокировки;
- действуют одинаковые правила безопасного просмотра;
- точное место скрывается от пользователей без доступа;
- статус встречи обновляется во всех карточках;
- дублирующие сообщения не создаются без явного повторного действия пользователя.
Автор встречи и другой пользователь могут поделиться встречей, если:
- встреча доступна текущему пользователю;
- встреча не удалена;
- встреча не отменена;
- встреча не прошла;
- нет блокировки между пользователями;
- пользователь имеет право видеть и отправлять эту встречу.

26. ФОТОГРАФИИ И БЕЗОПАСНЫЙ ДОСТУП
==================================================
В посте разрешено до 1 фотографий.
Во встрече разрешена только 1 фотография.
Если фотография создана искусственным интеллектом, под ней обязательно показывай:
«Сгенерировано с ИИ»
Используй именно это написание во всех постах и встречах.
Неверифицированный пользователь видит фотографии с блюром.
Блюр не должен быть единственным способом защиты.
Если пользователь не имеет права доступа, ему нельзя передавать:
- оригинальную фотографию;
- запрещённые данные автора;
- точное место встречи;
- закрытые данные профиля.

27. НАДЁЖНОСТЬ И СОСТОЯНИЯ ЭКРАНОВ
==================================================
Для каждого важного экрана предусмотрены состояния:
- загрузка;
- пустой результат;
- ошибка;
- повторная попытка;
- нет сети;
- профиль недоступен;
- публикация недоступна;
- встреча недоступна.
При отсутствии сети показывай последние сохранённые данные и баннер:
«Нет сети. Показываем сохранённые данные»
При ошибке действия показывай:
- понятное сообщение;
- кнопку «Повторить»;
- сохранённый текст;
- сохранённые параметры;
- сохранённые фотографии, если они уже были загружены.
Повторная отправка не должна создавать дубликаты:
- постов;
- встреч;
- комментариев;
- запросов на встречи;
- жалоб;
- сообщений;
- изменений анкеты;
- приглашений;
- карточек встреч в чатах.
Если пользователь начал писать пост, сообщение или запрос, текст не должен исчезать после ошибки или случайного выхода.
Не показывай белый экран и не оставляй пользователя без объяснения.
Проверяй надёжность отправки всех типов сообщений:
- текста;
- голосового аудиосообщения;
- фотографии.
При ошибке ни один подготовленный материал не должен исчезать без объяснения. Для каждого неотправленного сообщения показывай статус «Не отправлено» и кнопку «Повторить».
Повторная отправка текста, аудио или фотографии не должна создавать дубль, если исходная отправка уже завершилась успешно.

29. СОХРАНЯЕМЫЕ ОГРАНИЧЕНИЯ
==================================================
Сохрани следующие ограничения:
- встречи только один на один;
- при нажатии «＋» доступны только пост и встреча;
- отдельного типа «Вопрос» нет;
- все пользователи могут писать друг другу без ограничений;
- блокировка и жалобы сохраняются;
- безопасный просмотр для неверифицированных пользователей сохраняется;
- точное место встречи раскрывается только после принятия запроса и только нужным участникам;
- новые основные вкладки без необходимости не добавляются;
- не добавляй свайпы;
- не добавляй групповые встречи;
- не добавляй групповые чаты;
- не добавляй рейтинги пользователей.
Свободная переписка между всеми пользователями является новым утверждённым правилом и заменяет прежнее ограничение начала чатов контекстами.

9. Применяет фильтр.
10. Проверяет сохранение фильтра после перехода между лентами.

Главный пользовательский путь:
Анкета → Поиск → Фильтры → Профиль → Пост или Встреча → Запрос или Чат → Уведомление → Принятие запроса → Точное место → Общий чат.
Главное правило переписки:
Все пользователи могут писать друг другу без ограничений, если между ними нет блокировки.
Главное правило встреч:
Встречи всегда только один на один.
Главное правило создания:
Через кнопку «＋» можно создать только пост или встречу.
Главное правило приватности:
Неверифицированный пользователь видит безопасную версию профиля, публикации, встречи и фотографий, а запрещённые данные не должны передаваться ему в полном виде.
Главное правило обмена:
Кнопка «Поделиться» под карточкой встречи позволяет:
- отправить встречу пользователю внутри Aitu Dating;
- открыть системное меню для WhatsApp, Telegram и других приложений;
- скопировать ссылку.
Кнопка «Поделиться» в уже открытом чате позволяет выбрать встречу и отправить её текущему собеседнику.
Все способы используют ссылку на одну конкретную встречу и один общий чат между пользователями.
