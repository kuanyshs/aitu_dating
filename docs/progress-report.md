# Aitu Dating — отчёт о проделанной работе

_Состояние на 30 сентября 2026. Ветка `claude/sweet-hypatia-gwvlba`, коммит `ccab045`._

## Коротко

С нуля собран интерактивный прототип Aitu Dating — закрытого verified-сообщества, где знакомство начинается с разговора, вопроса или безопасного плана встречи один на один, а не со свайпа.

- Прототип покрывает **весь продуктовый путь**: гость → вступление через Aitu Passport → анкета → участник, а дальше лента, публикации, ответы, реакции, профили, подписки, поиск, планы встреч и отклики, контекстные чаты, «Активность», жалобы, блокировка и модерация.
- Работает **в браузере телефона** (веб-версия) и в Expo Go. Светлая и тёмная темы.
- Данные — **реалистичный mock-сервер внутри приложения**: 12 участников сообщества, 20 публикаций, 55 комментариев, 6 планов, 3 чата. Всё, что пользователь делает, сохраняется между перезагрузками.
- Настоящего бэкенда, входа через Aitu Passport и оплаты **пока нет**: это следующий этап (см. раздел «Что дальше»).

Масштаб:

| | |
|---|---|
| Срок | 5 дней (26–30 сентября) |
| Спеки | 8, все закрыты |
| Тикеты | 49, все закрыты |
| Коммиты | 103 |

| Автотесты | 551 unit/контрактный тест, 40 e2e-сценариев, 72 визуальных эталона (36 состояний экранов × 2 темы) |

## Как посмотреть

Публичной ссылки пока нет: прототип запускается локально, одной командой.

1. Один раз установить Git и Node.js 22 (инструкция для Windows, macOS и Linux — в [README](../README.md)).
2. Выполнить:
   ```bash
   git clone https://github.com/kuanyshs/aitu_dating.git
   cd aitu_dating
   git checkout claude/sweet-hypatia-gwvlba
   corepack enable
   pnpm install
   pnpm web
   ```
3. Открыть `http://localhost:8081` и в DevTools включить вид телефона (например, iPhone 12/13, 390×844).

С телефона: `pnpm start` и QR-код в приложении Expo Go.

**Что попробовать за 10 минут:**

1. Полистать ленту как гость: у авторов не видно имён, только пол, возраст и город.
2. «Вступить» → выбрать личность Passport (Айдана, Тимур или Мадина) → правила → «Бесплатный verified» → карточка → 7 вопросов анкеты → «Создать карточку».
3. Открыть пост, ответить, лайкнуть комментарий, сделать репост.
4. «Создать» → написать вопрос с темой.
5. Открыть чужой профиль, подписаться. Открыть план встречи из ленты, откликнуться.
6. «Профиль → Настройки → Demo controls»: истечь membership и посмотреть, как всё переходит в режим «Продлить»; включить роль модератора и разобрать жалобы; включить offline.

## Что умеет продукт

### 1. Гость, вступление и участник (спека #1)

- **Гость** сразу видит ленту сообщества в **безопасном виде**: только пол, возраст, город и нейтральный силуэт. Имя, фото, интересы и намерение не уходят с «сервера» вообще — это проверено тестами на уровне данных, а не только интерфейса.
- **Фильтры ленты:**
  - «Для тебя»;
  - «Популярное»;
  - «В городе» (город выбирается);
  - «Планы»;
  - «Подписки» — только участнику.
- **Любое социальное действие гостя** (лайк, ответ, репост, создание) открывает единый путь вступления, а не молча ничего не делает.
- **Путь вступления:**
  - Aitu Passport (mock: три личности, данные только для чтения);
  - правила клуба с обязательной галочкой;
  - выбор ровно одного периода membership: 1 / 3 / 6 / 12 месяцев (1 990 / 4 990 / 8 490 / 14 990 ₸, «Выгоднее» у 3 месяцев) или отдельно «Бесплатный verified» на 12 месяцев;
  - демо-оплата без ввода карты, с обработкой и понятной ошибкой с повтором;
  - карточка: «О себе» до 160 символов, 1–5 интересов, стиль общения;
  - 7 вопросов анкеты с прогрессом N/7.
- **Путь можно закрыть на любом шаге** и продолжить позже с того же места.
- **«Выйти» / «Войти»:** выход в гостевой режим не теряет карточку и публикации; вернуться можно без повторной анкеты.
- **Истёкший membership:**
  - своя карточка видна и редактируется;
  - другие люди — только в безопасном виде;
  - социальные действия ведут в «Продление» — выбор периода без повторной анкеты.
- **Ограничение модерацией:** отдельный экран с объяснением, правилами и поддержкой; контент человека скрыт от всех.

### 2. Публикация и ответы (спека #12)

- Полноэкранный экран поста:
  - пост целиком;
  - «Ответы · N» с сортировкой «Популярные / Новые»;
  - ветка в два уровня (комментарий → ответ).
- Отдельная поверхность «Ответ» с лимитом 360 символов. Ответ на ответ невозможен ни в интерфейсе, ни на сервере.
- Лайки постов и комментариев, репосты чужих постов. Интерфейс обновляется мгновенно и откатывается с тостом, если действие не прошло.
- Удаление своего комментария («Комментарий удалён», если на него отвечали) и своего поста («Публикация недоступна» по ссылке).
- Гость видит «Присоединяйтесь к разговору / Вступить», истёкший — «Продлить».

### 3. Создание (спека #19)

- Редактор поста и вопроса (до 1000 символов, до 4 тем) и цитаты чужого или своего поста.
- Черновик: при закрытии редактора с текстом — «Сохранить черновик / Удалить». При следующем открытии — «Продолжить черновик / Начать заново».
- После публикации свой пост первым в ленте у автора в течение 24 часов.
- «Мои публикации» в профиле.
- Сбой сети не теряет текст и не создаёт дубль при повторе.

### 4. Безопасность (спека #25)

- **Жалоба** на пост, комментарий, профиль или план:
  - 5 причин, пояснение до 500 символов;
  - экран «Жалоба отправлена» с предложением заблокировать автора;
  - повторная жалоба не создаёт дубль.
  - Гость может пожаловаться анонимно.
- **Блокировка** работает в обе стороны: посты, комментарии, профиль, планы и чаты исчезают у обоих, подписки снимаются.
- **Экран «Безопасность»:**
  - 5 советов для первой встречи;
  - «Заблокированные» с разблокировкой;
  - «Мои жалобы» со статусом и итогом.
- **Модерация** (роль модератора):
  - очередь «Новые / На рассмотрении / Решённые»;
  - решения «Отклонить», «Удалить контент» и «Ограничить участника»;
  - решение закрывает все открытые жалобы на ту же цель.

### 5. Профили и поиск (спека #33)

- **Чужой профиль:** карточка, счётчики, публикации, «Подписаться», метка «Взаимная подписка», жалоба и блокировка через «•••».
- **Списки** «Подписчики» и «Подписки».
- **Поиск:**
  - людей — по имени, «О себе» и интересам, с фильтрами город / интересы / намерение; без текста показываются люди своего города;
  - публикаций — по тексту и темам;
  - планов — по описанию, с фильтрами город / цель / формат.
- **Редактирование своей карточки** с вопросом «Отменить изменения?» при уходе.

### 6. Планы встреч (спека #40)

Главная механика продукта — встреча один на один в публичном месте.

- **Экран плана** зависит от роли:
  - гость видит сводку без точного места;
  - активный участник видит место и «Откликнуться»;
  - автор видит список откликов.
- **Создание плана:**
  - город, дата (на 14 дней вперёд), время с шагом 30 минут, формат, длительность, цель, кто платит;
  - место с обязательной галочкой «Это публичное место»;
  - описание и темы.
  - Не больше 3 открытых будущих планов.
- **Отклики:**
  - сообщение до 360 символов;
  - откликнувшийся может отозвать отклик и откликнуться снова;
  - автор принимает один отклик — план становится «Встречей», остальные отклоняются автоматически.
- **Статусы:**
  - «Встреча договорена»;
  - «Набор закрыт»;
  - «Отменён»;
  - «Прошёл» — считается по времени.
  - Метки видны в ленте; автор видит счётчик ожидающих откликов.
- «Мои планы» и «Мои отклики» в профиле.

### 7. Чаты и «Активность» (спека #47)

- **Контекстный чат** — один на пару людей. Открывается только из понятного контекста:
  - из чужого комментария («Написать» в «•••»);
  - при взаимной подписке (кнопка в профиле);
  - из договорённой встречи (у обоих участников).

  Чат помнит, с чего начался: «Из комментария», «Взаимная подписка», «Встреча: …».
- **Список чатов** — вход с Главной, со счётчиком непрочитанных.
- **Экран чата:**
  - сообщения до 1000 символов;
  - «Отправлено / Прочитано»;
  - «Показать ранние»;
  - неотправленное сообщение с «Повторить»;
  - жалоба и блокировка.
  - Участник с истёкшим membership читает, но не пишет.
- **Вкладка «Активность»:**
  - события: подписки, комментарии, ответы, реакции, репосты, отклики и решения по ним, скорое окончание membership;
  - категории: «Все», «Подписки», «Разговоры», «Реакции», «Планы», «Система»;
  - нажатие ведёт к посту, плану или человеку;
  - точка на вкладке, пока есть новое.

### 8. Полировка (спека #53)

- **«О продукте»:** что такое клуб, три принципа, правила клуба, безопасность, пометка «Демо-прототип, данные вымышлены».
- **«Membership»:** тариф, период, даты, статус, сколько дней осталось, «Продлить».
- **Метки «новое»** в «Активности» держатся весь заход во всех категориях.
- **Демо-время** продолжает идти между перезагрузками, поэтому порядок записей всегда верный.
- **Экран «Создать»** по ссылке: выбор «Пост / Вопрос / План».

## Сквозные свойства

- **Приватность по ролям на уровне данных.** Гость и участник с истёкшим membership физически не получают имён, фото и анкет других людей. Будущий бэкенд обязан вести себя так же — это закреплено в контрактных тестах.
- **Ни одной «мёртвой» кнопки.** Каждое недоступное действие объясняет, почему, и ведёт к решению: вступить, войти или продлить. Единственное исключение — «Обратиться в поддержку»: пока показывает «Скоро».
- **Надёжность действий.** Повтор после сбоя сети не создаёт дублей (idempotency). Введённый текст не теряется. Есть режим offline с баннером «Нет сети».
- **Состояния экранов.** У каждого экрана есть загрузка (скелетон), пустое состояние с объяснением, ошибка с «Повторить» и «недоступно» для удалённого или скрытого.
- **Доступность.**
  - Подписи для скринридера у иконок, «нажато» у лайков и репостов.
  - Зоны нажатия не меньше 44×44.
  - Контраст текста проверен по WCAG AA в обеих темах.
- **Темы:** системная, светлая и тёмная (в стиле Threads), выбор сохраняется.

## Демо-панель (для тестирования)

«Профиль → Настройки → Demo controls»:

- **Личность и доступ:**
  - сменить личность Aitu Passport (данные остальных сохраняются);
  - истечь или восстановить membership;
  - поставить или снять ограничение;
  - включить роль модератора.
- **Сбои:**
  - один раз вызвать ошибку сети;
  - один раз не отправить сообщение в чате;
  - включить offline.
- **«Сбросить демо»** — вернуть всё к исходному состоянию.

В production-сборке панель выключается флагом и не попадает в код.

## Известные ограничения прототипа

- **Всё хранится в браузере.** Два человека на разных устройствах не видят действий друг друга. Нужен бэкенд.
- **Aitu Passport и оплата — имитация.** Реальных интеграций нет.
- **Новый участник начинает «с чистого листа».** У только что вступившей личности нет чатов, откликов и событий в «Активности»: они появляются, только когда с ней взаимодействуют. Готовые чаты и события есть у seed-участников сообщества, но войти за них без инструментов разработчика нельзя. _Если продакт-менеджеру это важно для показа, можно быстро добавить в демо-панель «Войти как участник сообщества»._
- **Фото — синтетические абстрактные аватары**, загрузки фото нет.
- **Нет:**
  - push- и email-уведомлений;
  - истории оплат;
  - медиа в постах и чатах;
  - упоминаний;
  - групповых чатов;
  - редактирования опубликованного.
- **«Обратиться в поддержку»** — заглушка.
- **«Правила клуба»** — черновик, финальный текст утвердит юрист.
- **Публичной ссылки нет**, только локальный запуск.

## Техническая основа (кратко)

- **Приложение:** Expo SDK 57 (React Native + web), TypeScript, Expo Router, TanStack Query.
- **Контракт API:** 63 метода, описаны схемами Zod. Это готовая спецификация будущего бэкенда: он реализует тот же интерфейс, а экраны не меняются.
- **Mock-сервер** реализует все 63 метода: роли и урезание данных, ошибки сети, идемпотентность, пагинацию, миграции сохранённого состояния.
- **Тесты:**
  - контрактные тесты проверяют поведение «сервера» и потом без изменений запустятся против настоящего бэкенда;
  - Playwright проверяет пользовательские сценарии и пиксельное совпадение 36 состояний экранов в двух темах.

## Что дальше: бэкенд

После правок продакт-менеджера план — настоящий бэкенд для мобильной веб-версии. iOS и Android пока не делаем. Предварительные решения уже приняты на интервью:

| Тема | Решение |
|---|---|
| Хостинг | Облако в Казахстане (Yandex Cloud kz1 или PS.kz): закон РК о персональных данных |
| Стек | TypeScript (Node + Hono), PostgreSQL, в том же репозитории, на тех же контрактах |
| Вход | Aitu Passport (нужен партнёрский доступ), до его получения — SMS-код с ручной верификацией |
| Оплата | На старте только бесплатный verified, платёжный провайдер — позже |
| Фото | Загрузка одного фото профиля, модерация по жалобам |
| Обновления в реальном времени | Поток событий (SSE) для новых сообщений и «Активности» |
| Модерация и админка | В самом приложении плюс служебные команды с журналом действий |
| Уведомления | Только внутри приложения; Web Push — позже |
| Запуск | Закрытая бета по инвайт-кодам |
| Обязательно к запуску | Удаление аккаунта, поддержка, мониторинг и бэкапы, защита от спама |

Порядок работ:

1. Фундамент сервера.
2. Вход и инвайты.
3. Весь домен на сервере.
4. Чаты и realtime.
5. Фото.
6. Готовность к проду и запуск беты.

**Что понадобится со стороны бизнеса:**

- аккаунт в облаке РК;
- запрос партнёрского доступа к Aitu Passport;
- SMS-провайдер;
- домен;
- тексты политики конфиденциальности, согласия на обработку ПД и финальных правил клуба.
